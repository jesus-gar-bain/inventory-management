System Architecture

Factory Inventory Management System

A demo full-stack inventory, order, and spend analytics dashboard. A Vue 3 single-page application reads from a stateless FastAPI service that loads seven JSON fixtures into memory at import time. There is no database, no authentication, and no persistence layer.

Vue 3.4 · Composition API Vite 5 · :3000 FastAPI · :8001 Python · uv 14 GET endpoints read-only

Architecture

Four layers. The browser holds all view state; the server holds all data and does all filtering. Nothing is written back — every request is a read.

In-memory means read-only, by construction
mock_data.py calls json.load() once at import, binding each dataset to a module-level list. Handlers filter copies and never mutate those lists, and no endpoint writes to disk. Restarting the server resets everything to the committed fixtures.

Data Flow

One unidirectional cycle, triggered on mount and re-run whenever a filter changes. Raw server responses land in refs; everything displayed is derived in computed properties.

1
A filter changes
FilterBar binds to the four refs exported by useFilters — time period, warehouse, category, order status. Because those refs live at module scope, every view shares one instance and sees the change immediately.
2
A watcher refetches
Each view runs watch([selectedPeriod, selectedLocation, selectedCategory, selectedStatus], loadData). getCurrentFilters() maps the UI names onto API names — selectedLocation becomes warehouse, and selectedPeriod becomes month only when it is not all.
3
api.js builds the query string
Each method assembles a URLSearchParams, dropping any filter whose value is all so it never reaches the wire. Dashboard issues four calls in a single Promise.all — summary, orders, inventory, backlog.
4
FastAPI filters in memory
apply_filters() narrows by warehouse, then category, then status — category and status compared case-insensitively. filter_by_month() then matches either a literal YYYY-MM prefix or expands a quarter such as Q3-2025 through QUARTER_MAP, testing against each record's order_date.
5
Pydantic validates the response
Endpoints declaring a response_model coerce and prune each dict to the declared shape, so a fixture field missing from its model is silently dropped. Aggregate endpoints (/dashboard/summary, /reports/*, /spending/*) return plain dicts instead.
6
Refs in, computed out
Responses are assigned to raw refs — allOrders, inventoryItems, summary. Every displayed number is a computed property over those refs: status splits, category rollups, order trends, top products, chart geometry. Templates read only computed values, so a single refetch repaints the whole view.
Two filter asymmetries worth knowing
  • /api/inventory accepts only warehouse and category — inventory records carry no date field, so the time-period filter cannot apply to stock levels.
  • /api/demand, /api/backlog and every /api/spending/* endpoint ignore filters entirely and always return the full fixture. Filtering for those views, where it happens at all, happens client-side in computed properties.

Six client methods target endpoints that do not exist
api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, pointing at /api/tasks and /api/purchase-orders. Neither route is registered in main.py, so these calls return 404.
  • The four task methods are called from App.vue, where each is wrapped in a try/catch that only logs to the console. The task list still renders, because it merges the hard-coded tasks from useAuth with the API list that never arrives. The failure is invisible in the UI.
  • The two purchase-order methods are currently unreferenced by any component.
purchase_orders.json exists and is loaded, but is an empty array — so /api/backlog reports has_purchase_order: false for all four backlog items.

Running Locally

Two processes. The client hard-codes http://localhost:8001/api, so the API must be up first.

ProcessCommandServes
Backendcd server && uv run python main.pyAPI on :8001, OpenAPI UI at /docs
Frontendcd client && npm install && npm run devSPA on :3000
Testscd tests && uv run pytest backend/ -vBackend endpoint suites
Demo posture, not production
No authentication — useAuth returns a fixed user with isAuthenticated hard-coded to true. CORS allows all origins. There is no rate limiting and no secret management. The API base URL is a literal in api.js rather than an environment variable, so pointing the client anywhere else means editing source.
